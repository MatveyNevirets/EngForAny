# Публикация engforany2 на Netlify

Репозиторий настроен для **Next.js со встроенным API**, а не для статического HTML. `netlify.toml` задаёт сборку и каталог результата, `.nvmrc` — версию Node.js. Netlify автоматически подключает адаптер OpenNext, создающий в том числе серверную функцию для `/api/leads`.

## Подключить репозиторий

1. Загрузите содержимое этого репозитория в свой GitHub / GitLab / Bitbucket. В корне должны находиться `package.json`, `package-lock.json`, `netlify.toml`, `.nvmrc` и папка `src`. Не помещайте их внутрь ещё одной папки `engforany2`.
2. В Netlify выберите **Add new project → Import an existing project**, подключите Git-провайдера и выберите `engforany2` и нужную ветку.
3. Настройки будут прочитаны из `netlify.toml`. Если Netlify показывает поля вручную:

   | Поле | Значение |
   | --- | --- |
   | Framework | Next.js |
   | Base directory | Пусто (корень репозитория) |
   | Package directory | Пусто |
   | Build command | `npm run build` |
   | Publish directory | `.next` |
   | Node.js | `24` |

4. Нажмите **Deploy**. Дождитесь завершения сборки и обработки адаптером Next.js. После этого откройте адрес из результата деплоя.

Публикуйте исходники через **Import an existing project**. Загрузка папки как готовой статики не эквивалентна сборке Next.js: обычный dropzone может ожидать `index.html`, которого в корне этого проекта нет. Не загружайте `src` или `.next` отдельно как готовый статический сайт и не добавляйте правило `/* /index.html 200`: оно не создаёт сервер Next.js и может ломать API.

Если у уже созданного сайта сохранились неправильные настройки, исправьте их в Build settings, затем выполните **Retry deploy → Clear cache and deploy site**. Проверьте, что сайт связан именно с репозиторием и сборка действительно запускает Next.js и OpenNext.

## Переменные окружения

Для демонстрации секреты и ручная настройка домена **не нужны**. `ALLOW_INDEXING=false` задан в `netlify.toml`; реальные отправки в MAX не подключены.

- `DEPLOY_PRIME_URL` и `URL` задаются самим Netlify. Код использует их для адресов OG и проверки Origin формы, включая deploy previews и работу за HTTPS-прокси.
- `SITE_URL` необязателен. Указывайте его только для постоянного собственного домена, например `https://english.example.ru`. Удалите старое значение `http://localhost:3000`, если оно было добавлено в Netlify вручную.
- Не переносите локальные `.env.local`, `.next`, `node_modules`, токены или пароли в Git.
- Перед реальным выпуском подтвердите документы и реквизиты и подключите доставку, как описано в README. Для снятия noindex измените `ALLOW_INDEXING` в `netlify.toml` и пересоберите сайт.

## После публикации

Проверьте `/`, `/robots.txt`, `/icon.svg` и форму: заполнение + галочка согласия → успех с пояснением о деморежиме. `GET /api/leads` закономерно отвечает **405**, поскольку API принимает только `POST`. Это не поломка.

Если всё ещё 404, откройте **Deploys → последний deploy → Deploy log**. Нужен журнал сборки, а не только текст страницы 404. Сборка должна закончиться без ошибки и содержать этап OpenNext / Next.js runtime. Ни один деплой не выполнялся агентом в рамках подготовки репозитория.

## Локальная проверка

```bash
npm ci
npm run build
node --test tests/site-origin.test.mjs
npx --yes netlify-cli build --offline
```

Последняя команда проверяет сборку Netlify локально и ничего не публикует. Впервые ей нужен интернет для скачивания CLI и адаптера; ключ `--offline` отключает обращения CLI за настройками сайта и авторизацией, но не установку пакетов сборки.

Документация: [Next.js на Netlify](https://docs.netlify.com/build/frameworks/framework-setup-guides/nextjs/overview/), [локальная сборка CLI](https://cli.netlify.com/commands/build/).
